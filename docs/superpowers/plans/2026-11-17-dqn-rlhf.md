# RLHF (Reinforcement Learning from Human Feedback) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mở rộng hệ thống DQN với cơ chế RLHF (Human-in-the-Loop Online Fine-tuning): cho phép chuyên viên HR tương tác đồng ý hoặc ghi đè quyết định của AI trực tiếp trên giao diện web, kích hoạt cập nhật gradient nơ-ron theo thời gian thực và đồng bộ trọng số mô hình.

**Architecture:** Bổ sung phương thức `learnFromHumanFeedback` vào `DQNAgent` trong TypeScript; xây dựng endpoint Express `POST /api/v1/rl/feedback`; bổ sung cột tương tác RLHF trên bảng Live Decision Board trong `DQNScreening.jsx` để cập nhật $Q$-values tức thì khi nhận phản hồi từ HR.

**Tech Stack:** Node.js, TypeScript, Express 5, React 19, Recharts, React Icons, CSS.

**Spec:** `docs/superpowers/specs/2026-11-17-dqn-rlhf-design.md`

## Global Constraints

- 100% mã nguồn Backend viết bằng TypeScript, thực thi qua `tsx`.
- Tuyệt đối KHÔNG commit bất kỳ tệp `.env` nào. Khi `git add` chỉ thêm đích danh các tệp cần thiết.
- Tuân thủ công thức Reward Chế độ 2 trong `MDP.md`:
  - HR Đồng ý: $r_{human} = +2.0$.
  - HR Bác bỏ / Ghi đè: phạt hành động cũ $r = -2.0$, thưởng hành động mới của HR $r = +2.5$.
- Trọng số mô hình sau khi RLHF được cập nhật và lưu tại `backend/weights/dqn_baseline.json` (nằm ngoài `backend/src/`).
- Mỗi task kết thúc bằng một commit Git riêng biệt kèm test kiểm chứng.

## Review Focus

1. **Q-value thay đổi đúng hướng sau feedback:** Khi HR sửa từ REJECT thành ACCEPT, $Q(s, \text{ACCEPT})$ mới phải tăng lên so với trước khi feedback.
   * *Test:* Task 1 kiểm tra $Q_{new}(\text{ACCEPT}) > Q_{old}(\text{ACCEPT})$.
2. **Không làm suy giảm chất lượng toàn cục (Stability guard):** Gradient step của RLHF chỉ cập nhật với learning rate vừa phải ($\alpha = 0.0005$) kèm clipping $[-1, 1]$ để không làm đảo lộn toàn bộ mạng nơ-ron.
   * *Test:* Task 1 kiểm tra các giá trị Q-values không bị bùng nổ hay xuất hiện NaN.
3. **Phản hồi tức thì dưới 100ms:** API `/rl/feedback` phải phản hồi ngay lập tức để giao diện không bị giật lag.
   * *Test:* Task 2 đo thời gian phản hồi của handler.
4. **Hiển thị trực quan trạng thái đã xác thực trên UI:** Sau khi HR bấm feedback, dòng của ứng viên phải chuyển sang trạng thái "Đã xác nhận bởi HR" và cập nhật Q-values mới.
   * *Test:* Task 3 kiểm tra build frontend và state updates.
5. **Đồng bộ hóa trọng số vào bộ nhớ:** Instance của Agent trong controller phải phản ánh ngay trọng số mới cho các lần gọi `/simulate` tiếp theo.
   * *Test:* Task 4 kiểm tra E2E sau khi gửi feedback thì `/simulate` kế tiếp dùng ngay trọng số mới.
